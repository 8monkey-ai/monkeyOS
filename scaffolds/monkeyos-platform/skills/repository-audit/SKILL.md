# Repository audit

First run deterministic contract checks. Then evaluate whether the app would still be considered secure and maintainable if built today. Verify a conventional React Router Framework Mode structure, standard package scripts, project-level Bun configuration, and the generated production build; reject parallel entries, custom development orchestration, and custom Vite build plumbing. Require the `vite:react-compiler` transform selected from the official Vite React plugin with `oxc-transform-react` and `compiler: true`; React Router must retain JSX and Fast Refresh ownership, so reject both the full React plugin pipeline beside it and a restored Babel React Compiler pipeline. Verify focused Oxlint correctness/suspicious, React/accessibility, type-aware/type-check, and unused-suppression enforcement plus explicit Oxfmt Tailwind sorting; do not demand broad style/pedantic/restriction/nursery or heuristic `react-perf` policies without measured evidence. Verify that `components.json` uses the Base UI nova preset, `ui:add` uses the installed official CLI, standard primitives and the shell come from the registry, and application composition stays outside `src/components/ui/`; flag hand-written approximations of available registry components. Reject invented placeholder business schema/CRUD and routine Supabase `.from()`/`.rpc()` access from routes or visual components. Verify real modules own typed TanStack Query hooks with stable keys, validation, errors, and precise cache updates while RLS remains authoritative. Review dependencies and compatible-update automation, latest stable Bun, Auth, memberships, RLS, audit coverage, PII/retention, external boundaries, local/production secrets, browser/API security, architecture-matched container delivery, current Actions, deployment, tests, README accuracy, AGENTS.md enforcement, and managed-file drift. Verify that protected `RUNTIME_ARCH` consistently selects provider compute/image defaults, CI, manifest verification, Kamal, and provisioned configuration. Enumerate every business skill routed by `BUSINESS.md`; flag missing or unreferenced skills, overlapping authority, contradictions, stale behavior, broken references, and version/date-suffixed duplicates. Git is history; active skills must describe one current truth. Report material evidence as BLOCKING, IMPORTANT, or SUGGESTION and avoid style-only churn.
