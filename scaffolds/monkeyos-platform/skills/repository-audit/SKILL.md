# Repository audit

First run deterministic contract checks. Then evaluate whether the app would still be considered secure and maintainable if built today. Verify standard React Router Framework Mode files and Bun-forced commands, route modules, framework type generation, the generated Web Streams server build, and the thin `Bun.serve`/`createRequestHandler` adapter; reject Node runtimes/adapters/container bases, parallel browser entries, dev proxy/orchestration, application middleware, and custom Vite build plumbing. Verify that `components.json` uses the Base UI nova preset, `ui:add` invokes `shadcn@latest`, standard primitives and the shell come from the official CLI registry, and application composition stays outside `src/components/ui/`; flag hand-written approximations of available registry components. Reject invented placeholder business schema/CRUD and routine Supabase `.from()`/`.rpc()` access from routes or visual components. Verify real modules own typed TanStack Query hooks with stable keys, validation, errors, and precise cache updates while RLS remains authoritative. Review dependencies and compatible-update automation, latest stable Bun, Auth, memberships, RLS, audit coverage, PII/retention, external boundaries, local/production secrets, browser/API security, architecture-matched container delivery, current Actions, deployment, tests, README accuracy, AGENTS.md enforcement, and managed-file drift. Verify that protected `RUNTIME_ARCH` consistently selects provider compute/image defaults, CI, manifest verification, Kamal, and provisioned configuration. Enumerate every business skill routed by `BUSINESS.md`; flag missing or unreferenced skills, overlapping authority, contradictions, stale behavior, broken references, and version/date-suffixed duplicates. Git is history; active skills must describe one current truth. Report material evidence as BLOCKING, IMPORTANT, or SUGGESTION and avoid style-only churn.
